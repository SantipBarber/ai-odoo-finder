# AI-OdooFinder Backend API

**Language**: [English](README.md) | [Español](README.es.md)

FastAPI backend for searching Odoo modules with hybrid search (vector embeddings + BM25-style full-text search).

> **Self-hosted only.** This REST API is meant for self-hosted deployments. The public server (`https://addon-finder.eticco.es`) only exposes MCP at `/` and `/health`; `/search`, `/stats` and the other REST endpoints are not public.

## Overview

The backend provides the REST API and the hybrid search engine behind AI-OdooFinder. It indexes 19,700+ Odoo modules from OCA repositories and enables module discovery through:

- **Vector Search**: Semantic similarity using Qwen3-Embedding-4B embeddings (2560 dimensions), generated via the OpenRouter API
- **Full-Text Search**: Keyword search with PostgreSQL `tsvector` (`searchable_text` column, ranked with `ts_rank_cd`)
- **Hybrid Search**: Combines both rankings using Reciprocal Rank Fusion (RRF, `k=60`)
- **Version Filtering**: Odoo 12.0 through 19.0
- **AI Enrichment**: Descriptions, tags and keywords generated by Grok-4-fast via OpenRouter

## Quick Start

### Prerequisites

- Python 3.14+ (the root `pyproject.toml` requires `>=3.14`; the Docker image uses `python:3.12-slim` with pinned dependencies)
- PostgreSQL 17 with the pgvector extension (the Docker Compose setup uses `pgvector/pgvector:pg17`)
- [uv](https://docs.astral.sh/uv/)
- An [OpenRouter](https://openrouter.ai/) API key (required: query embeddings and enrichment)

### Installation

All commands below are run from the **repository root**: `pyproject.toml` and `.env.example` live there, and the backend reads `.env` from the current working directory.

1. **Clone the repository:**
```bash
git clone https://github.com/SantipBarber/ai-odoo-finder.git
cd ai-odoo-finder
```

2. **Install dependencies:**
```bash
uv sync
```

3. **Set up environment variables:**
```bash
cp .env.example .env
```

Edit `.env`:
```bash
# Database (same database/user as docker-compose.yml)
DATABASE_URL=postgresql://odoofinder:your_password@localhost:5432/ai_odoofinder
POSTGRES_DB=ai_odoofinder
POSTGRES_USER=odoofinder
POSTGRES_PASSWORD=your_password

# APIs
OPENROUTER_API_KEY=your_openrouter_api_key   # required
GH_TOKEN=                                    # must be defined; may be empty (only used by the ETL)

# App
ENVIRONMENT=development

# Embedding (optional, these are the defaults)
# EMBEDDING_MODEL=qwen/qwen3-embedding-4b
# EMBEDDING_DIMENSIONS=2560
```

`postgresql://` URLs are converted automatically to `postgresql+psycopg://`.

4. **Start PostgreSQL with pgvector:**
```bash
docker compose up -d db
```

The SQL files in `backend/migrations/` are mounted into `/docker-entrypoint-initdb.d`, so PostgreSQL runs them automatically **only the first time** the data volume is initialized. `001_init_extensions.sql` enables the `vector` and `pg_trgm` extensions. `001` also creates the `odoo_modules` table (mirroring `backend/app/models.py`), and `002`–`005` add full-text search, enrichment fields and indexes on top of it. Rollback scripts live in `backend/migrations/rollback/`, which PostgreSQL ignores during initialization.

5. **Run the backend:**
```bash
# With auto-reload
uv run uvicorn backend.app.main:app --host 0.0.0.0 --port 8989 --reload

# Or with the helper script
uv run python scripts/run_server.py
```

The API will be available at `http://localhost:8989`.

### Search

#### `GET /search` or `POST /search`
Hybrid search for Odoo modules using natural language queries. Both methods take **query-string parameters only** (a JSON body is not read; without query parameters the request returns `422`).

**Parameters:**
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `query` | string | Yes | Natural language search query |
| `version` | string | Yes | Odoo version (`12.0` to `19.0`) |
| `dependencies` | string (repeatable) | No | Required dependency. Repeat the parameter for several values (`&dependencies=sale&dependencies=stock`); a module matches if it depends on **any** of them |
| `limit` | integer | No | Max results (1-50, default: 10) |
| `min_score` | integer | No | Minimum score (0-100, default: 0) |

**Example Request (GET):**
```bash
curl "http://localhost:8989/search?query=product+recommendation&version=17.0&limit=5"
```

**Example Request (POST):**
```bash
curl -X POST "http://localhost:8989/search?query=invoice+generation&version=16.0&limit=10&min_score=50"
```

**Example with dependencies:**
```bash
curl "http://localhost:8989/search?query=recurring+invoices&version=17.0&dependencies=account&dependencies=sale"
```

**Response:**
```json
{
  "query": "product recommendation",
  "version": "17.0",
  "dependencies": null,
  "total_results": 5,
  "results": [
    {
      "id": 1234,
      "technical_name": "sale_order_product_recommendation",
      "name": "Sale Order Product Recommendation",
      "version": "17.0",
      "summary": "Recommend products to sell to customer based on history",
      "description": "Sale Order Product Recommendation...",
      "depends": ["sale"],
      "author": "Tecnativa, Odoo Community Association (OCA)",
      "license": "AGPL-3",
      "repo_name": "sale-workflow",
      "repo_url": "https://github.com/OCA/sale-workflow",
      "module_path": "sale_order_product_recommendation/__manifest__.py",
      "github_stars": 358,
      "github_issues_open": 12,
      "last_commit_date": "2025-11-06T10:30:00",
      "score": 89,
      "rrf_score": 0.0185,
      "vector_score": 0.82,
      "bm25_score": 0.45
    }
  ]
}
```

(`id`, `github_issues_open`, scores and dates are illustrative.)

**Response Fields:**
- `score`: Score 0-100 derived from the RRF score (`min(100, rrf_score × 6000)`)
- `rrf_score`: Raw Reciprocal Rank Fusion score
- `vector_score`: Cosine similarity (`1 - cosine distance`); `null` if the module only matched full-text
- `bm25_score`: Full-text relevance (`ts_rank_cd`); `null` if the module only matched by vector
- `description`: Truncated to 200 characters

## Search Algorithm

The hybrid search uses **Reciprocal Rank Fusion (RRF)** to combine the vector and full-text rankings:

```
RRF_score = 1/(k + rank_vector) + 1/(k + rank_bm25)
```

Where `k=60` (standard RRF constant). A module found by only one method gets only that term.

### Search Flow

1. **Query Embedding**: Generate a 2560-dimensional vector with `qwen/qwen3-embedding-4b` through the OpenRouter API
2. **Vector Search**: Exact cosine distance scan with pgvector (`<=>` operator), filtered by version (and dependencies), top 50 candidates. There is no vector index: pgvector cannot index `vector` columns with 2560 dimensions
3. **Full-Text Search**: `plainto_tsquery('english', …)` against `searchable_text`, ranked with `ts_rank_cd`, top 50 candidates
4. **Fusion**: Combine both rankings with RRF and keep the top `limit`
5. **Normalization**: Convert the RRF score to the 0-100 `score` and apply `min_score`

The `searchable_text` column is maintained by a database trigger that weights `technical_name`/`name` (A), `summary`/`ai_description`/`keywords`/`repo_name` (B), `description`/`functional_tags` (C) and `readme` (D).

> `SearchService` also has internal `vector` and `bm25` modes (used by the benchmark scripts). They are not exposed through the REST API, which always uses `hybrid`.

## Database Schema

### `odoo_modules` Table

Created by the ORM model (`backend/app/models.py`) and extended by the SQL migrations in `backend/migrations/`.

```sql
CREATE TABLE odoo_modules (
  -- Basic Info
  id SERIAL PRIMARY KEY,
  technical_name VARCHAR NOT NULL,   -- not unique: one row per module and version
  name VARCHAR NOT NULL,
  version VARCHAR NOT NULL,

  -- Dependencies
  depends VARCHAR[],

  -- Metadata
  author VARCHAR,
  license VARCHAR,                   -- ORM default: 'AGPL-3'

  -- Content
  summary VARCHAR,
  description TEXT,
  readme TEXT,

  -- Repository
  repo_name VARCHAR NOT NULL,
  repo_url VARCHAR,
  module_path VARCHAR,

  -- GitHub
  github_stars INTEGER,
  github_issues_open INTEGER,
  last_commit_date TIMESTAMP,

  -- Search
  embedding VECTOR(2560),
  searchable_text TSVECTOR,          -- migration 002, maintained by trigger

  -- AI Enrichment (migration 003)
  ai_description TEXT,
  functional_tags TEXT[],
  keywords TEXT[],
  enriched_at TIMESTAMP,
  enrichment_version VARCHAR(20),

  -- Clean content (migration 005, not mapped in models.py)
  description_clean TEXT,
  content_source VARCHAR(50),
  content_extracted_at TIMESTAMP,

  -- Timestamps
  created_at TIMESTAMP,
  updated_at TIMESTAMP
);
```

**Indexes:**

| Index | Definition | Source |
|-------|------------|--------|
| `ix_odoo_modules_id` | `id` | ORM (`index=True`) |
| `ix_odoo_modules_technical_name` | `technical_name` | ORM (`index=True`) |
| `ix_odoo_modules_version` | `version` | ORM (`index=True`) |
| `idx_modules_fulltext` | GIN (`searchable_text`) | Migration 002 |
| `idx_modules_needs_enrichment` | `enriched_at` WHERE `enriched_at IS NULL` | Migration 003 |
| `idx_modules_functional_tags` | GIN (`functional_tags`) | Migration 003 |
| `idx_modules_keywords` | GIN (`keywords`) | Migration 003 |
| `idx_modules_needs_content_extraction` | `content_extracted_at` WHERE `content_extracted_at IS NULL` | Migration 005 |
| `idx_modules_content_source` | `content_source` | Migration 005 |

There is no vector index on `embedding` (see [Search Flow](#search-flow)).

## Configuration

### Environment Variables

Read by `backend/app/config.py` (Pydantic Settings) from the environment or from a `.env` file in the current working directory.

| Variable | Default | Description |
|----------|---------|-------------|
| `DATABASE_URL` | - | PostgreSQL connection string (**required**) |
| `OPENROUTER_API_KEY` | - | OpenRouter API key (**required**): query embeddings and AI enrichment |
| `GH_TOKEN` | - | GitHub token used by the ETL. **Must be defined** (no default), but may be empty |
| `ENVIRONMENT` | `development` | Free-form environment label |
| `LOG_LEVEL` | `INFO` | Logging level (`DEBUG`, `INFO`, `WARNING`, `ERROR`) |
| `EMBEDDING_MODEL` | `qwen/qwen3-embedding-4b` | Optional. Embedding model on OpenRouter |
| `EMBEDDING_DIMENSIONS` | `2560` | Optional. Must match the `VECTOR(2560)` column |

Logging is fixed at `INFO` level in `main.py`.

### Settings

```python

print(settings.database_url)
print(settings.embedding_model)
```

## Troubleshooting

### Startup fails with a validation error

`DATABASE_URL`, `OPENROUTER_API_KEY` and `GH_TOKEN` must all be defined (in `.env` or the environment). `GH_TOKEN` can be empty. Run the server from the repository root so `.env` is found.

### Database Connection Issues

**Error:** `psycopg.OperationalError: connection failed`

1. **Verify PostgreSQL is running:**
```bash
docker compose ps db
psql "postgresql://odoofinder:your_password@localhost:5432/ai_odoofinder" -c "SELECT 1;"
```

2. **Check the `DATABASE_URL` format:**
```bash
postgresql://user:password@host:5432/database_name
```

3. **Check the extensions:**
```bash
psql "postgresql://odoofinder:your_password@localhost:5432/ai_odoofinder" -c "\dx"
```

### Search returns no results or errors

Query embeddings come from the OpenRouter API. If embedding generation fails, the search logs `Error generating embedding` and returns an empty list.

1. **Check `OPENROUTER_API_KEY`** is valid and the account has credit.
2. **Verify modules are indexed:**
```bash
curl http://localhost:8989/stats
```
3. **Check the version** has modules (`by_version` in `/stats`) and is between `12.0` and `19.0`.

## Performance Notes

### Vector search

Vector search is an exact cosine-distance scan (`ORDER BY embedding <=> query`), filtered first by `version` (indexed). pgvector cannot index `vector` columns with 2560 dimensions, so there is no approximate vector index.

### Full-text search

`searchable_text` is indexed with GIN (`idx_modules_fulltext`).

### Caching

There is currently no caching: every search calls OpenRouter for the query embedding and runs both queries. `cache_service.py` exists but is not used by the search path.

### Connection Pooling

SQLAlchemy is configured with connection pooling:
```python
engine = create_engine(
    database_url,
    pool_pre_ping=True,      # Verify connections before use
    pool_recycle=3600,       # Recycle connections after 1 hour
)
```

## Deployment

### Docker

The backend `Dockerfile` is at the repository root (build context: repository root):

```bash
# Build image (from the repository root)
docker build -t ai-odoofinder-api .

# Run container
docker run -d \
  --name ai-odoofinder-api \
  -p 8989:8989 \
  -e DATABASE_URL="postgresql://odoofinder:your_password@db-host:5432/ai_odoofinder" \
  -e OPENROUTER_API_KEY="..." \
  -e GH_TOKEN="" \
  ai-odoofinder-api
```

### Docker Compose

`docker-compose.yml` (repository root) defines three services:

| Service | Image / build | Port | Notes |
|---------|---------------|------|-------|
| `db` | `pgvector/pgvector:pg17` | 5432 | Runs `backend/migrations/*.sql` on first initialization |
| `api` | `Dockerfile` (root) | 8989 | This backend |
| `mcp` | `mcp-server/Dockerfile` | 8080 | MCP server in HTTP mode (`MCP_PATH=/`), calls `http://api:8989` |

```bash
# Start all services
docker compose up -d

# View API logs
docker compose logs -f api
```

`POSTGRES_PASSWORD` and `OPENROUTER_API_KEY` must be set in `.env`. See [Deployment & Operations](../docs/en/DEPLOYMENT_OPERATIONS.md) for the full guide.
