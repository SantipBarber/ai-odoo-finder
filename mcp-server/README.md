# AI-OdooFinder MCP Server

**Language**: [English](README.md) | [Español](README.es.md)

MCP (Model Context Protocol) server for semantic search of Odoo modules in the OCA ecosystem.

## Overview

This MCP server provides a tool called `search_odoo_modules` that enables LLMs to search through 19,700+ indexed Odoo modules from OCA repositories using hybrid search (semantic + BM25).

## Quick Start

### Option 1: Public remote server (recommended, no install)

The easiest way to use AI-OdooFinder is the public remote MCP server hosted by [Eticco](https://www.eticco.es):

```
https://addon-finder.eticco.es
```

- **Transport**: Streamable HTTP
- **Authentication**: None for OCA community modules

Add that URL to your MCP client. STDIO-only clients can use the [`mcp-remote`](https://www.npmjs.com/package/mcp-remote) bridge: `npx -y mcp-remote https://addon-finder.eticco.es`. For per-client configurations, see the [main project README](../README.md#installation).

### Option 2: Local STDIO package (self-hosted backend)

This package is available on **[PyPI](https://pypi.org/project/ai-odoofinder-mcp/)**. It runs the MCP server locally over STDIO and talks to the FastAPI backend REST API. The public instance does not expose that REST API, so use this mode with **your own backend deployment** (see [Deployment & Operations](../docs/en/DEPLOYMENT_OPERATIONS.md)).

```bash
# Using pip
pip install ai-odoofinder-mcp

# Using uvx (recommended for MCP clients)
uvx ai-odoofinder-mcp
```

MCP client configuration:

```json
{
  "mcpServers": {
    "ai-odoofinder": {
      "command": "uvx",
      "args": ["ai-odoofinder-mcp"],
      "env": {
        "AI_ODOOFINDER_API_URL": "http://localhost:8989"
      }
    }
  }
}
```

> **Note**: Requires [uv](https://docs.astral.sh/uv/) package manager installed.

## Features

- **Hybrid Search**: Combines semantic search (embeddings) with BM25 full-text
- **Version Filtering**: Only shows compatible modules (Odoo 14.0 to 19.0)
- **AI Enrichment**: Descriptions, tags, and keywords generated by Grok-4-fast
- **Intelligent Flow**: Smart clarifications, query expansion, confidence levels

```
┌─────────────────┐
│   MCP Client    │ (Claude Desktop, Zed, Cursor, etc.)

└────────┬────────┘
         │
         │ MCP (STDIO or Streamable HTTP)
         │
┌────────▼────────┐
│   MCP Server    │ (This component)
│  FastMCP + uv   │
└────────┬────────┘
         │
         │ HTTP (REST)
         │
┌────────▼────────┐
│   Backend API   │ (FastAPI + PostgreSQL)
│   :8989         │
└─────────────────┘
```

**Two modes:**
- **STDIO** (default): for local clients that launch the server as a subprocess (e.g. Claude Desktop with `uvx ai-odoofinder-mcp`)
- **HTTP** (Streamable HTTP, port `8080`, path `/`): for remote clients. Enable it with `--http` or `MCP_TRANSPORT=http`

## Tools

### `search_odoo_modules`

Search for Odoo modules using natural language queries.

**Parameters:**
- `query` (string, required): Search query in natural language
- `version` (string, required): Odoo version, from `14.0` to `19.0` (e.g. `"16.0"`, `"17.0"`)
- `dependencies` (list of strings, optional): Filter by required dependencies, e.g. `["account"]`
- `limit` (integer, optional): Max results (default: 5, max: 20; out-of-range values are clamped to 1–20)

**Returns:**
- Markdown text with the modules found, the confidence level and guidance for the assistant

**Example:**
```json
{
  "query": "electronic invoicing for Spain",
  "version": "16.0",
  "limit": 5
}
```

## Intelligent Search Flow

The server implements an intelligent search flow:

1. **Clarification**: Asks for details if query is generic or missing version
2. **Query Expansion**: Adds ES/EN synonyms, localization prefixes (`l10n_XX_`)
3. **Structured Response**: Returns results with confidence levels:
   - **HIGH** (score ≥80): Detailed format with recommendations
   - **MEDIUM** (50-79): Summary format with alternatives
   - **LOW** (<50): Suggestions to refine search
4. **Confirmation**: Validates with user if found what they were looking for

## Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `AI_ODOOFINDER_API_URL` | `http://localhost:8989` | Backend API URL |
| `AI_ODOOFINDER_API_TIMEOUT` | `60` | API timeout in seconds |
| `MCP_TRANSPORT` | `stdio` | Transport: `stdio` or `http` (`--http` forces `http`) |
| `MCP_HOST` | `0.0.0.0` | Bind host in HTTP mode (overridden by `--host`) |
| `MCP_PORT` | `8080` | Port in HTTP mode (overridden by `--port`) |
| `MCP_PATH` | `/` | MCP endpoint path in HTTP mode |

## API Integration

The MCP server connects to the FastAPI backend at the URL specified in `AI_ODOOFINDER_API_URL`.

**Backend endpoint used:**
- `GET /search` - Hybrid search

**Search algorithm:**
1. Generate embedding for query (Qwen3-Embedding-4B via OpenRouter)
2. Vector search (pgvector, exact cosine distance)
3. BM25 full-text search (PostgreSQL tsvector)
4. Combine results with Reciprocal Rank Fusion (RRF)

```
RRF_score = 1/(k + rank_vector) + 1/(k + rank_bm25)
```

Where `k=60` (standard RRF constant)

## Troubleshooting

### Server doesn't start

1. **Check `uv` is installed:**
   ```bash
   uv --version
   ```

2. **Check Python version:**
   ```bash
   python --version  # Should be 3.11+
   ```

3. **Reinstall dependencies:**
   ```bash
   uv sync --reinstall
   ```

### Connection to API fails

1. **Verify the service is up:**
   ```bash
   # Public instance
   curl https://addon-finder.eticco.es/health

   # Self-hosted backend
   curl http://localhost:8989/health
   ```

2. **Check timeout settings:**
   ```bash
   export AI_ODOOFINDER_API_TIMEOUT=120
   ```

### MCP client doesn't see the tool

1. **Check MCP client logs** for connection errors
2. **Verify JSON-RPC is working**: Use MCP Inspector
3. **Restart MCP client completely**
